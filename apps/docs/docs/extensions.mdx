# Extensions, DICOM and image processing

The core `@niivue/niivue` package views images. Heavier jobs, such as
converting DICOM or running image filters, live in separate extension
packages so you only ship what you use. Each one that works on NiiVue
objects lists `@niivue/niivue` as a peer dependency, so install it alongside
the extension (`nv-ext-niimath` is standalone). The packages are in prerelease, published
under the `next` tag:

```bash
npm install @niivue/niivue@next
```

Most extensions run their work in a Web Worker, so the page stays
responsive while they compute.

## DICOM: dcm2niix

```bash
npm install @niivue/dcm2niix@next
```

NiiVue does not read DICOM directly. `@niivue/dcm2niix` runs dcm2niix
(compiled to WebAssembly) in the browser and returns NIfTI series you can
load:

```js
import { convert } from '@niivue/dcm2niix'

// <input id="dicomFolder" type="file" webkitdirectory multiple />
input.addEventListener('change', async () => {
  // A nonzero exit still returns the series that converted.
  const { series } = await convert(input.files)
  await nv.loadVolumes([{ url: series[0].image }])
})
```

Each series also carries its `json` sidecar and any `bval`/`bvec`. For a
dropped folder, `filesFromDataTransfer(e.dataTransfer.items)` collects the
files first; `listSeries` lists series without converting them. The
`Dcm2niix` class gives full control over the dcm2niix flags:

```js
import { Dcm2niix } from '@niivue/dcm2niix'

const dcm2niix = new Dcm2niix()
await dcm2niix.init()
const result = await dcm2niix.input(files).compressionLevel(9).bids('n').run()
```

[Live demo](https://niivue.github.io/mono/demo-ext-dcm2niix/)

## Filters: nv-ext-niimath

```bash
npm install @niivue/nv-ext-niimath@next
```

`@niivue/nv-ext-niimath` runs [niimath](https://github.com/rordenlab/niimath)
(an fslmaths clone) on a NIfTI file. Each step is one niimath operation, and
the steps run in order:

```js
import { Niimath, runNiimathPipeline } from '@niivue/nv-ext-niimath'

const niimath = new Niimath() // create one per page; the worker is costly
await niimath.init()

const result = await runNiimathPipeline(niimath, file, [
  { method: 's', args: [3] }, // smooth, sigma 3 mm
  { method: 'thr', args: [0.5] },
  { method: 'bin', args: [] },
])
await nv.loadVolumes([{ url: new File([result], 'processed.nii.gz') }])
```

[Live demo](https://niivue.github.io/mono/demo-ext-niimath/)

## Segmentation: nv-ext-image-processing

```bash
npm install @niivue/nv-ext-image-processing@next
```

`@niivue/nv-ext-image-processing` provides volume transforms: `otsu`
(threshold into 2 to 4 classes), `removeHaze`, `conform` and
`connectedLabel`. You register them on an extension context and apply them
to a loaded volume:

```js
import { otsu } from '@niivue/nv-ext-image-processing'

const ctx = nv.createExtensionContext()
ctx.registerVolumeTransform(otsu)

const segmented = await ctx.applyVolumeTransform('otsu', ctx.volumes[0])
await ctx.addVolume(segmented)
```

## Drawing tools: nv-ext-drawing

```bash
npm install @niivue/nv-ext-drawing@next
```

`@niivue/nv-ext-drawing` works on the drawing layer. It can find the first
and last drawn slices, fill the slices between them by interpolation, and
run a 3D magic wand (`magicWand`) from a seed point:

```js
import { SLICE_TYPE } from '@niivue/niivue'
import { interpolateMaskSlices } from '@niivue/nv-ext-drawing'

const ctx = nv.createExtensionContext()
const dr = ctx.drawing
if (dr) {
  const filled = await interpolateMaskSlices(
    dr.bitmap, dr.dims, null, 1, undefined, undefined,
    { sliceType: SLICE_TYPE.AXIAL },
  )
  dr.update(filled)
}
```

See [Drawing and segmentation](./drawing) for painting the drawing itself.

## Export: nv-ext-save-html

```bash
npm install @niivue/nv-ext-save-html@next
```

`@niivue/nv-ext-save-html` saves the current scene as one self-contained
HTML file that opens without a server. You supply the NiiVue code to embed,
as a standalone ES module bundle with all dependencies inlined:

```js
import { saveHTML } from '@niivue/nv-ext-save-html'

const bundleSource = await fetch('/niivue-standalone.js').then((r) => r.text())
await saveHTML(nv, 'scene.html', { niivueBundleSource: bundleSource, title: 'My scene' })
```

`generateHTML(nv, options)` returns the same page as a string instead of
downloading it.

[Live demo](https://niivue.github.io/mono/demo-ext-save-html/)

## Tiled slides: nv-ext-tile

```bash
npm install @niivue/nv-ext-tile@next
```

`@niivue/nv-ext-tile/tiff` streams tiled/pyramidal TIFF, BigTIFF, OME-TIFF and
Aperio SVS slides into `NVSlide` over HTTP Range, reading and decoding
(with [@niivue/geotiff-rs](https://github.com/rordenlab/geotiff-rs)) only the tiles in
view. The server must answer Range requests with `206` and allow them
cross-origin; one that sends the whole file is refused.

```js
import { NVSlide } from '@niivue/niivue'
import { TiffSlideSource } from '@niivue/nv-ext-tile/tiff'

const source = await TiffSlideSource.fromUrl('https://example.org/slide.svs')
const slide = NVSlide.fromSource(source)
// when done: slide.dispose() also disposes the source it owns;
// pass { ownsSource: false } to keep a shared source and dispose it yourself
```

`createSlideView(canvas, { slide })` from `@niivue/niivue` then runs the
renderer (WebGPU, falling back to WebGL2), the frame loop, resize and the
pan/zoom gestures; `view.destroy()` releases all of it.

`TiffSlideSource.fromGeoTIFF(await fromBlob(file))` opens a local file;
`registerDcm2niixTiffDecoders()` adds JPEG 2000 tiles (Aperio SVS) through
`@niivue/dcm2niix`.
`@niivue/nv-ext-tile/dicom` opens DICOM-WSI folders (`indexDicomWsi`,
`DicomWsiSource`); `registerDcm2niixDecoders()` adds JPEG 2000 and JPEG-LS
tiles and ICC colour management through `@niivue/dcm2niix`.
DICOM-WSI label, overview and thumbnail images are listed in
`index.associated` (`associatedImages`, `associatedImageBitmap`), never as slides.
`@niivue/nv-ext-tile/zarr` loads OME-Zarr volumes (`loadOmeZarrVolumes`) or
streams them (`streamOmeZarr`); see [Loading](./loading).

`@niivue/nv-ext-tile/open` opens any of these, loading only the format it finds.
It lists every slide the input holds and never picks one:

```js
import { NVSlide } from '@niivue/niivue'
import { openSlide } from '@niivue/nv-ext-tile/open'

// A URL (TIFF, OME-Zarr, DZI, hosted DICOM-WSI manifest), or local files
// (TIFFs and DICOM-WSI folders); `fetch` adds auth to every read.
const { candidates } = await openSlide(input, { fetch, signal })
const slide = NVSlide.fromSource(await candidates[0].open())
// slide.dispose() disposes the source
```

Vendor TIFF layouts open too: Philips padded levels, NDPI (as virtual JPEG
tiles), Argos focal stacks, and, with `{ tiff: { placement: true } }`, Ventana
tile joints, Trestle overlaps and Leica regions as placed tiles.

[Live demo](https://niivue.github.io/mono/demo-ext-tile/)
