# demo-ext-tile

Demo app for [`@niivue/nv-ext-tile`](../../packages/nv-ext-tile): open a tiled/pyramidal TIFF, BigTIFF, OME-TIFF or Aperio SVS whole-slide image, a DICOM-WSI slide (hosted manifest or local files), a 2D OME-Zarr store, or a Deep Zoom (DZI) image, and pan/zoom it with `NVSlide` + `SlideRendererGPU` (WebGPU) or `SlideRenderer` (WebGL2). Only the tiles in view are read and decoded.

```bash
bun install                    # From monorepo root
bunx nx dev demo-ext-tile      # Dev server on port 8092
```

- **Slide menu** streams by HTTP Range: OpenSlide's [CMU-1-Small-Region.svs](https://media.githubusercontent.com/media/niivue/niivue-demo-images-lfs/main/streaming/svs/CMU-1-Small-Region.svs) (GitHub LFS, opened on load) and the OpenSlide test slides that stream as single TIFF files (JPEG 2000 SVS included; their tiles decode in `@niivue/dcm2niix` workers), mirrored on Hugging Face (`neurodeskorg/webapps`, pinned commit). **DICOM-WSI** entries are the hosted `dicom-wsi-range-v1` manifests in the same LFS repo (`streaming/dicom-wsi/`); their `.dcm` files are read by Range from GitHub's LFS media endpoint (raw serves LFS pointers). JPEG 2000 and JPEG-LS tiles decode in `@niivue/dcm2niix` workers. **OME-Zarr** entries are 12 2D OME-Zarr 0.5 stores on Hugging Face (`omezarr2d/`, pinned commit), opened with `ZarrSlideSource`; each store's `attribution` (title, credit or citation, licence) shows at the bottom right. The OpenSlide TIFF and DICOM-WSI entries show their [OpenSlide test data](https://openslide.cs.cmu.edu/download/openslide-testdata/) credit and licence there too (from its `index.json`). Three uint8 channels show as RGB; other stores show one channel (the first omero-active) in grey, windowed from omero when usable, else the data range. **Deep Zoom (DZI)** opens OpenSeadragon's highsmith example with core's `DziSource` (no extension; tiles are plain HTTP requests, no Range).
- **Custom URL...** opens a tiled TIFF/SVS, a hosted DICOM-WSI manifest when the path ends in `.json` (one DICOM-WSI slide spans several files, so a single `.dcm` URL is not enough), an OME-Zarr store when it ends in `.zarr` or `/`, or a DZI descriptor when it ends in `.dzi`. The server must answer `206` and allow the request cross-origin (CORS with `Range`; DZI tiles are plain GETs, so DZI needs CORS only); a TIFF server that ignores Range is refused after its first response, but a manifest's `.dcm` files from such a server are read whole (HTTP 200 in the HUD). `?url=<url>` opens one on load (`?url=` starts empty).
- **Custom files...** reads local files, nothing is uploaded. One TIFF (sniffed from its first bytes) opens with `fromBlob`; otherwise the files are indexed as DICOM-WSI (`indexDicomWsi`; headers only), each slide (optical path, focal-plane index `z`, levels, transfer syntax, sparse, frames and holes; skipped files are in the status tooltip) is listed in a **Series** menu and the first opens. JPEG 2000 and JPEG-LS tiles decode in `@niivue/dcm2niix` workers. Index timings are in the [package README](../../packages/nv-ext-tile#local-dicom-wsi-folders).
- **Level** pins a pyramid level (auto LOD by default). **Filter** switches linear and nearest tile sampling. **Colour management** (on by default) applies the slide's ICC profile. **Grid** outlines each drawn tile. **HUD** (or the `I` key) shows the slide, backend, filter, pixel ratio, drawn level, codec, zoom, tiles, requests, wire bytes, cache and failures; tile failures also reach the status line.
- **Backend** (WebGPU, falling back to WebGL2) and **AA** (multisample, both backends; off by default on WebKit) reload the page with `?backend=` / `?aa=`, keeping a remote slide via `?url=` (local files are dropped). **HiDPI** (on) draws at the display's pixel ratio; off draws one canvas pixel per CSS pixel. It is disabled on a 1x display and re-checked when the pixel ratio changes (another monitor, browser zoom).

OME-Zarr pages (moved from core's examples):
- `ome.zarr.html`: open a multiscale store, pick a level and channels, load it whole.
- `range.html`: stream a volume brick by brick over HTTP Range (a synthetic shard, written by `scripts/generate-range-poc-fixture.ts` before each dev or build, or an OME-Zarr store). Stores are read from `public/omezarr/` when present, else from the public Open SciVis bucket; `bun scripts/fetch-omezarr.ts --list` shows what can be downloaded there. Only the small `stent` store is in git. Serve it with `bunx nx dev demo-ext-tile`: core's dev server (port 8080) serves the app under `/demo-ext-tile/`, but `range.html` looks for its synthetic fixture at the site root.
- `vox.block.pick.zarr.html`: pick an exploded block of a streamed HiP-CT heart and re-stream it at full resolution.

- `bunx nx e2e demo-ext-tile` (about 1 s, not in CI) builds the demo and checks the DICOM-WSI custom-files workflow, and that a failed Custom URL open keeps the Slide and Series menus, in headless Chromium on the package's synthetic fixtures.
