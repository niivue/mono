# demo-ext-tile

Demo app for [`@niivue/nv-ext-tile`](../../packages/nv-ext-tile): open a tiled/pyramidal TIFF, BigTIFF, OME-TIFF or Aperio SVS whole-slide image, a DICOM-WSI slide (hosted manifest or local files), a 2D OME-Zarr store, or a Deep Zoom (DZI) image, and pan/zoom it with core's `createSlideView` (`NVSlide` on `SlideRendererGPU` or `SlideRenderer`, one frame loop and teardown). Only the tiles in view are read and decoded.

```bash
bun install                    # From monorepo root
bunx nx dev demo-ext-tile      # Dev server on port 8092
```

- **Slide menu** streams by HTTP Range: OpenSlide's [CMU-1-Small-Region.svs](https://media.githubusercontent.com/media/niivue/niivue-demo-images-lfs/main/streaming/svs/CMU-1-Small-Region.svs) (GitHub LFS, opened on load) and the OpenSlide test slides that stream as single TIFF files (JPEG 2000 SVS included; their tiles decode in `@niivue/dcm2niix` workers), mirrored on Hugging Face (`neurodeskorg/webapps`, pinned commit). **DICOM-WSI** entries are the hosted `dicom-wsi-range-v1` manifests in the same LFS repo (`streaming/dicom-wsi/`); their `.dcm` files are read by Range from GitHub's LFS media endpoint (raw serves LFS pointers). JPEG 2000 and JPEG-LS tiles decode in `@niivue/dcm2niix` workers. **OME-Zarr** entries are 12 2D OME-Zarr 0.5 stores on Hugging Face (`omezarr2d/`, pinned commit), opened with `ZarrSlideSource`; each store's `attribution` (title, credit or citation, licence) shows in the status bar. The OpenSlide TIFF and DICOM-WSI entries show their [OpenSlide test data](https://openslide.cs.cmu.edu/download/openslide-testdata/) credit and licence there too (from its `index.json`). Three uint8 channels show as RGB; other multi-channel stores open composited (omero colours, windows and `active`); a single-channel store shows in grey, windowed from omero when usable, else the data range; a segmentation (`image-label`) shows with a label colormap. **Deep Zoom (DZI)** opens OpenSeadragon's highsmith example with core's `DziSource` (no extension; tiles are plain HTTP requests, no Range).
- **Custom URL...** and **Custom files...** open through `@niivue/nv-ext-tile/open` (`openSlide`). A URL is an OME-Zarr store when its path ends in `.zarr` or `/`, a DZI descriptor for `.dzi`, a hosted DICOM-WSI manifest for `.json` (one DICOM-WSI slide spans several files, so a single `.dcm` URL is refused), a tiled TIFF/SVS for a TIFF suffix, and otherwise whatever one 132-byte Range probe shows. The server must answer `206` and allow the request cross-origin (CORS with `Range`; DZI tiles are plain GETs, so DZI needs CORS only); a TIFF server that ignores Range is refused after its first response, but a manifest's `.dcm` files from such a server are read whole (HTTP 200 in the HUD). `?url=<url>` opens one on load (`?url=` starts empty).
- **Custom files...** reads local files, nothing is uploaded. TIFFs are known by their first bytes; the other files are indexed as DICOM-WSI (headers only; progress in the status line, abandoned when another slide is picked). Each TIFF and each DICOM slide (optical path, focal-plane index `z`, levels, transfer syntax, sparse, frames and holes; skipped files are in the status tooltip) is listed in a **Series** menu, in file order, and the first opens. A dual-personality DICOM-TIFF file is listed both ways. JPEG 2000 and JPEG-LS tiles decode in `@niivue/dcm2niix` workers. Index timings are in the [package README](../../packages/nv-ext-tile#local-dicom-wsi-folders).
- **Drag and drop** files or folders onto the page (outlined while dragging) to open them as Custom files; a dropped folder is walked recursively and its files keyed by their path in it, so same-named files in subfolders stay distinct.
- **Gestures** (core's `NVSlideController`): left or middle drag pans, right drag draws a box and zooms in to fit it, stopping at native resolution (it never zooms out, so a view already finer is kept), the wheel and a pinch zoom about the pointer, a double-click zooms in 2x (shift: out). **Drag** turns the left drag into window/level (x widens, y lowers the centre) or a contrast box (the window becomes the range of the loaded samples in it), on the channel picked in the channel panel. RGB slides have no window to set, so window/level and the contrast box are disabled for them and a slide opened in either mode falls back to pan.
- **Status bar** (fixed height, bottom): the slide's credit; while the pointer is over the slide, the values under it per channel, from the tiles loaded (`formatSlideSample`). Long text is cut off; its tooltip has all of it. The loading spinner sits at its right.
- **Channels** (multi-channel and monochrome slides): visibility, exact colour (`addChannelColormap`), window (data units) and blend, as native form controls (Tab, visible focus).
- **Compare** (off / side by side / lens): a second view of the same slide, beside this one or through a lens that follows the pointer (`linkSlideViews`, `attachSlideLens`), linked in physical units, with its own channel panel; shown only once it has opened.
- **Planes**: focal-plane and time sliders (`attachSlidePlaneControl`) for a slide that states `planes`; hidden for a fixed source.
- **Minimap**, **HUD**, the channel panel and the plane sliders come from `@niivue/uikit` (`attachSlideMinimap`, `attachSlideHud`, `attachSlideChannelPanel`, `attachSlidePlaneControl`); drop those calls and the dependency to remove them.
- **Level** pins a pyramid level (auto LOD by default). **Filter** switches linear and nearest tile sampling. **Scale bar** (on by default) draws a bottom-left bar from the slide's pixel spacing (OME-Zarr, local DICOM-WSI; none when unknown, as for TIFF/SVS and the hosted DICOM manifests). **Colour management** (on by default) applies the slide's ICC profile. **Grid** outlines each drawn tile. **HUD** (or the `I` key) shows the slide, backend, filter, pixel ratio, drawn level, codec, zoom, tiles, requests, wire bytes, cache and failures; tile failures also reach the status line.
- **Backend** (WebGPU, falling back to WebGL2) and **AA** (multisample, both backends; off by default on WebKit) reload the page with `?backend=` / `?aa=`, keeping a remote slide via `?url=` (local files are dropped). **HiDPI** (on) draws at the display's pixel ratio; off draws one canvas pixel per CSS pixel. It is disabled on a 1x display and re-checked when the pixel ratio changes (another monitor, browser zoom).

OME-Zarr pages (moved from core's examples):
- `ome.zarr.html`: open a multiscale store, pick a level and channels, load it whole; a time series shows its timepoint over the canvas, and a segmentation store added beside it switches frames with the channels, coloured by its `image-label` table.
- `range.html`: stream a volume brick by brick over HTTP Range (a synthetic shard, written by `scripts/generate-range-poc-fixture.ts` before each dev or build, or an OME-Zarr store). Stores are read from `public/omezarr/` when present, else from the public Open SciVis bucket; `bun scripts/fetch-omezarr.ts --list` shows what can be downloaded there. Only the small `stent` store is in git. Serve it with `bunx nx dev demo-ext-tile`: core's dev server (port 8080) serves the app under `/demo-ext-tile/`, but `range.html` looks for its synthetic fixture at the site root.
- `vox.block.pick.zarr.html`: pick an exploded block of a streamed HiP-CT heart and re-stream it at full resolution.

- `bunx nx e2e demo-ext-tile` (seconds; CI runs it on SwiftShader, `niivue-e2e.yml`) builds the demo and checks the DICOM-WSI custom-files workflow, that a failed Custom URL open keeps the Slide and Series menus, loose-file and folder drops (a fake entry tree: scripts cannot make real ones), the viewer shell on an in-memory 2-channel OME-Zarr store (status bar credit and readout with a fixed layout at 900 and 360 px, window/level and the contrast box off for an RGB store, keyboard channel panel, window/level, double-click zoom, side-by-side and lens), lazy OME-Zarr time with prefetch and a paired segmentation, and the OME-Zarr slide on nv-ext-tile's zarr-python variants (both backends), in headless Chromium, with no network. `DEMO_E2E_BACKENDS=webgl2` limits the time check to WebGL2. `bunx nx test demo-ext-tile` (`src/drop.test.ts`) checks the folder walker’s batching and paths.

- **Benchmark** (tile-stack baseline): `node bench/fetch.mjs` once downloads the pinned stores (CMU-1 SVS, a DICOM-WSI manifest, IMC 27-channel and Sentinel-2 uint16 OME-Zarr; about 870 MB) into `$TILE_BENCH_DATA` (default `~/.cache/niivue-tile-bench`). Then `TILE_BENCH_DATA=<dir> bunx nx bench demo-ext-tile` builds the demo with `bench/slide3d.html`, serves both and the stores on port 5397 (`BENCH_PORT`), and drives full Chromium on the real GPU, WebGPU and WebGL2, at 1920x1080 and DPR 2: open, first paint and sharp (every tile of the capacity-limited level drawn), requests and bytes per pan step and zoom-out, W/L frame time with and without the minimap, the 3D slide-plane load queue, and heap and GPU bytes after a 60 s pan. `?bench` exposes the view to it. JSON per run and `summary.md` go to `$BENCH_OUT`; `BENCH_REPEATS`, `BENCH_ONLY` and `BENCH_STORES` narrow a run (see the head of `bench/run.mjs`).
